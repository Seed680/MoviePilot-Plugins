# 企业微信通知范围修复

让企业微信渠道中由用户触发的消息也遵循 MoviePilot 的「通知发送范围」设置。

## 背景

MoviePilot 的通知路由对任何带用户标识的消息都会直接原样直发（`action=None`），
因此「通知发送范围」（`NotificationSwitchs`）在企业微信渠道内由用户触发的消息上
完全不生效：即使把「订阅」设置为 `user,admin`，管理员也收不到通知。

本插件在宿主通知路由状态机入口安装补丁（不修改宿主源码），为企业微信用户消息补回
发送范围处理，其余渠道行为保持不变。

## 生效规则

| 发送范围 | 实际投递 |
| --- | --- |
| `user`（仅用户） | 只回复发起交互的用户（与宿主原有行为一致） |
| `admin`（仅管理员） | 回复用户 + 追加管理员 |
| `user,admin` | 回复用户 + 追加管理员 |
| `all`（全部） | 回复用户 + 按渠道默认目标全员广播 |

- 回复用户的消息保持原样直发、立即投递，仍回到原会话。
- 追加的管理员/全员投递会清除原会话标识，按收件人自己的渠道设置或渠道默认目标发送，
  不会把消息重复发给发起用户。
- 只在企业微信渠道（`NotificationChannel.Wechat`）生效；Telegram、Web-Agent 等渠道不受影响。

## 使用说明

1. 安装本插件仓库后，在插件市场安装「企业微信通知范围修复」。
2. 打开插件配置，启用「启用企业微信通知范围修复」并保存。
3. 在 `设置 → 通知 → 通知发送范围` 中配置各场景的范围，微信渠道即按上表生效。

## 注意事项

- 「全部」在企业微信应用模式下会向应用全体成员广播（`userid` 为空即全员），请确认后再使用。
- 管理员追加投递仍遵循宿主既有规则：管理员账号需要绑定企业微信用户 ID，
  或渠道配置了默认目标（如 bot 模式的会话 ID），否则该条投递会被渠道丢弃。
- 插件通过补丁方式接管宿主内部的通知路由状态机；若宿主后续原生支持该行为，
  插件会自动让位（检测到宿主已产出路由范围时直接沿用宿主实现），无需额外处理。
- 停用插件或停止插件服务会立即恢复宿主原始实现。

## 实现说明

- 发送范围统一通过稳定 SDK `app.sdk.services.ServiceConfigHelper.get_notification_switch`
  读取，与宿主的 `通知发送范围` 配置同源。
- 路由补丁只在启用时安装：包装 `app.chain._messaging._notification_route_steps`
  （宿主未提供公开的通知路由扩展点），并在函数上保留原始实现，停用、重载或插件卸载
  时立即还原；重复启用不会重复包装。
- 补丁内部复用宿主的通知路由状态机处理管理员查找、`admin,all` 去重和未知路由回退，
  不复制宿主的用户设置查询逻辑。
- 宿主已经自行处理微信用户消息范围（路由入口产出非空范围）时，插件直接沿用宿主实现，
  不会重复投递。
